## User events / workordermanagement

### workordermanagement（`usereventworkordermanagement.htm`）

**用途**：enhanced workordermanagement-system（強化的工單管理系統）。

可使用下列事件：

- **strukturinit**：設定 treeview（樹狀檢視）要使用的變數。
  - 可設定的變數：

    | 變數 | 說明 |
    |---|---|
    | wostlselect | 在物料（material）位置中檢視用的 select 指令 |
    | wpafoselect | 在途程（routing）位置中檢視用的 select 指令 |

  - Information：較好的做法是直接在工單結構視窗（work order structure window）的視窗設定（window settings）中定義。
- **timerecordingstart**：在工時記錄（time recording）開始時。
  - 可讀取的變數：`e_belnr_id`、`e_belpos_id`、`e_pos_id`（routing-pos）、`e_row`（來自目前的 datastore，內部使用；若以 master-slave 方式處理 slave 項目，則 > 1）、`e_pers_id`
  - 若 return failure，流程會被取消，並顯示錯誤訊息 1100 "Error in timerecordingstart"。
- **timerecordingend**：在工時記錄結束時。
  - 可讀取的變數：見 timerecordingstart
  - `ojdt_transid`：產生的日記帳分錄（journal entry）
  - `ojdt_transid_storno`：若 Beas 建立了沖銷（cancellation）日記帳分錄，則為其在 ojdt 中的 ID
  - `e_itemstampid`：在 beas_arbzeit 中的 ID（buchnr_id）

（本頁無 Read/Write 變數表。）

> ⚠ 原文疑似不一致：本總覽頁的 timerecordingend 列出的變數（`e_belnr_id`、`e_belpos_id`、`e_pos_id`、`e_row`、`e_pers_id`、`ojdt_transid`、`ojdt_transid_storno`、`e_itemstampid`）與獨立頁面 TimeRecordingEnd（`ue_workordermanagement_timerecordingend.htm`）的變數表（`e_WoDocEntry`、`e_WoLineNumber`、`e_Employee`、`e_TimeReceiptJournalEntry` 等）完全不同；錯誤碼也不同（本頁 timerecordingstart 為 1100，TimeRecordingEnd 頁為 1101）。兩頁均未說明兩組變數名稱的對應或新舊關係。

### PreCalculationInit（`precalculation.htm`）

**執行時機**：在預先計算（pre-calculation）開始前執行（Pre calculation、Batch Calculation）。

**用途**：用於定義擴充屬性（extended properties）。

| 變數 | 讀 | 寫 | 說明 |
|---|---|---|---|
| checkLotSizeFirstLevel |  | ✔ | 定義系統是否必須在第一層（first Level）就檢查 productionLotsize。（詳見下方） |
| useCalculationLotSize |  | ✔ | 定義系統依批量（Lotsize）分割子組件（sub-assemblies）的方式。（詳見下方） |
| lotSizeCalculationType |  | ✔ | 定義子組件中批量計算的類型（原文：「Definee type of Lot size calclulation in sub assemblies」）。（詳見下方） |

**checkLotSizeFirstLevel**

- Beas 2020.11 及更舊版本：系統只在子組件中檢查此項。
- Beas 2020.12 及更新版本：系統從第一層開始檢查。
- 若要使用與 Beas 2020.11 相同的功能，必須將此屬性改為 false。

原文範例（逐字）：

```
// checkLotSize only in subassembly for older precalculation

// Use Lotsize Calculation for all pre calculation whith docment number < 1520
if <str_parm.belnr_id> n< 1520 then
  setvar=checkLotSizeFirstLevel=false
end if
end function
```

> ⚠ 原文疑似不一致：此範例只有 `end function` 而沒有對應的 `function PreCalculationInit` 開頭行；且範例內的註解寫「Use Lotsize Calculation for all pre calculation ...」，與上一行註解「checkLotSize only in subassembly ...」及所設定的變數 `checkLotSizeFirstLevel` 主題不同（該註解與下方 useCalculationLotSize 範例的註解相同）。

**useCalculationLotSize**

- Beas 2020.11 及更舊版本：系統使用 Calculation Lot size（計算批量）來分割子組件。
- Beas 2020.12 及更新版本：系統使用 Production Lot size（生產批量）來分割子組件。

若要使用與 2020.11 相同的概念：

```
function PreCalculationInit
setvar=useCalculationLotSize=true
end function
```

相容模式（compatibility mode）註記：若希望舊的計算結果與以前相同，且您曾使用分割子組件，可以指定計算單號（Calculation Number），其儲存在 `str_parm.belnr_id`：

```
function PreCalculationInit
// Use Lotsize Calculation for all pre calculation whith docment number < 1520
if <str_parm.belnr_id> n< 1520 then
  setvar=useCalculationLotSize=true
end if
end function
```

**lotSizeCalculationType**

範例：

- Lot size Calculation：100
- Lot size Production：60

預設計算（Variant 1）：production lot size 只是每張生產工單的最大數量。若生產 100 Pcs，系統計算 60 + 40 Pcs，並使用總價。

舊計算類型（Variant 2）：production lot size 是下列的倍數：（原文此句到冒號即結束）若生產 100 Pcs，系統計算 2x60 Pcs，但只使用 100 Pcs 的價格。

（原文此處附兩張示意圖：lotsizecalculationnew、lotsizecalculationvariant2。）

Notes：

- 若使用 Variant 2，表示您以錯誤的方式使用 production lot size。此變體僅為相容性而提供。
- 在 Beas 2020.11 及更舊版本，系統使用的是「Lot size calculation」。請參閱參數「useCalculationLotSize」。

若使用 Variant 1，不需要做任何變更。若要使用 Variant 2，必須插入下列程式碼：

```
// Use old calculation for lot size
function PreCalculationInit
setvar=lotSizeCalculationType=2
end function
```

### PostCalculation（`ue_workordermanagement_postcalculation.htm`）

**執行時機**：在建立事後計算（post calculation）之前執行。

可以用 return failure 取消此工單位置（work order position）的計算。

Note：若這是倒沖（backflushing）流程的一部分，而您嘗試取消入庫（receipt）流程，系統無法回滾（roll back）屬於整個倒沖流程一部分的發料（issue）流程。

此事件在下列情況執行：

- 每一次入庫流程的計價（pricing）
- 結案工單（Close work order）
- 手動啟動計算或批次事後計算（batch post calculation）

| 變數 | 讀 | 寫 | 說明 |
|---|---|---|---|
| e_WoDocEntry | ✔ |  | 工單號碼（Work order number） |
| e_WoLineNumber | ✔ |  | 工單位置（Work order Position） |

### setres_reservation（`ue_workordermanagement_setres_reservation.htm`）

**用途**：為預留（Reservation）視窗中的預先指派（Pre-Assign）定義規則。

更多資訊請見 PreAssign（即 Preassign 頁）。（原文附圖 Issue_pre-assign。）

| 變數 | 讀 | 寫 | 說明 |
|---|---|---|---|
| e_res_dfltwhs | ✔ | ✔ | 取料或預留時的預設倉庫（詳見下方） |
| e_res_whscode_std | ✔ | ✔ | 預先指派時所考慮的倉庫（詳見下方） |
| e_res_filter | ✔ | ✔ | 決定要考慮哪些 BoM 位置的篩選條件（詳見下方） |

**e_res_dfltwhs**：取料或預留時的預設倉庫。

預設儲存下列值：

```
case when ifnull("BEAS_FTSTL"."WhsCode",'') <> '' then "BEAS_FTSTL"."WhsCode"  else "OITM"."DfltWh" end
```

若要在 Reservation 視窗中總是以同一個倉庫作為預設：

```
function setres_reservation
setvar=e_res_dfltwhs=('01')
end function
```

重要：要加括號，否則 ' 字元可能會被誤解。或者使用 `setvar=e_res_dflthws="'01'"`。

可用資料表：BEAS_FTSTL、BEAS_FTPOS、BEAS_FTHAUPT、OITM、O2（組件的 OITM）、BEAS_ME、BEAS_AGTYP

**e_res_whscode_std**：預先指派時所考慮的倉庫。

可用資料表：

- OITM、OWHS
- 批號物料：OBTN、OBTQ
- 序號物料：OSRN、OSRQ

取料一律依以下優先順序：

1. 預留（Reservation）（此開關無作用）
2. 分配倉庫（Allocation warehouse）——若有包含在清單中
3. 預設倉庫，可被倉庫清單覆寫。無法進一步定義排序。

在 configuration wizard 中設定的取料排序會套用於批號與序號。

若要額外考慮預設倉庫，請插入佔位符 "*****"：

```
function e_res_issuewo
setvar=e_res_whscode_std="OWHS"."WhsCode" in ('*****','01','02')
end functoin
```

**e_res_filter**：決定要考慮哪些 BoM 位置的篩選條件。用於決定要為哪些 BoM 位置建立預留或分配。

可用資料表：BEAS_FTSTL、BEAS_FTPOS、BEAS_FTHAUPT、OITM、O2（組件的 OITM）、BEAS_ME、BEAS_AGTYP

範例：預留時，只考慮批號相關物料中，其物料群組（material group）欄位 "UDF1" 填入 "Y" 者。

```
function setres_reservation
setvar=e_res_filter= <cr_lf>and ("OITM"."ManBtchNum"<>'Y' or coalesce((select "BEAS_MATGRP"."UDF1" from "BEAS_MATGRP" &
      where "BEAS_MATGRP"."GRUPPE" = "OITM"."U_gruppe"),'N')='Y')
end function
```

**為什麼沒有 WoDocEntry / WoLineNumber？**

原因：在預留清單中可能有不只一張工單。您必須在 SQL 查詢中定義規則。

```
// reservation: User "1" has only access to warehouse 01 and 02
function setres_reservation
if <currentuser> = "1" then
  setvar=e_res_whscode_std="OWHS"."WhsCode" in ('01','02')
end if
end function
```

> ⚠ 原文疑似不一致：(1) 替代寫法 `setvar=e_res_dflthws="'01'"` 的變數名為 `e_res_dflthws`，與表中 `e_res_dfltwhs` 拼寫不同；(2) e_res_whscode_std 範例的函式名為 `function e_res_issuewo`（與變數同前綴，而非事件名 `setres_issuewo`），且結尾為 `end functoin`；(3) e_res_filter 範例說明寫「consider only batch-related items」，但條件是 `"OITM"."ManBtchNum"<>'Y' or ...`。
