## 問題明細

### [⚠不屬實] usereventworkordermanagement.htm — 第 102 行 ⚠ 標註的後半句(錯誤碼)
- 嚴重度:中(⚠ 會誤導讀者以為原文有矛盾)
- 原文:總覽頁只寫了 timerecordingstart 的錯誤碼:「if you return failure, the process is canceled with error message 1100 "Error in timerecordingstart"」。timerecordingend 段落沒有錯誤碼。TimeRecordingEnd 頁寫的是:「Error message: "1101: Error in timerecordingEnd"」。
- 目前中文:「錯誤碼也不同(本頁 timerecordingstart 為 1100,TimeRecordingEnd 頁為 1101)」
- 問題:這裡拿「start 事件的錯誤碼」去比「end 事件的錯誤碼」。兩者本來就是不同事件,1100/1101 是連號,看不出矛盾。總覽頁也沒有替 timerecordingend 給錯誤碼,所以沒有可比較的對象。至於前半句說兩組變數名稱完全不同,這點屬實(見下方屬實表)。
- 建議修正:刪除「錯誤碼也不同(…)」這句,只保留變數名稱不同的部分。或改寫為:「(本頁只給出 timerecordingstart 的錯誤碼 1100;TimeRecordingEnd 頁的錯誤碼為 1101,兩者為不同事件。)」

### [增譯] ue_workordermanagement_createworkorderbom.htm — 第 398 行「註」
- 嚴重度:低
- 原文:(無對應內容)
- 目前中文:「註:`createworkorder` 一列的「讀/寫」依 HTML 表格為「讀 ✔」;指定的 vars.py 腳本只輸出 `e_` 開頭的列,未列出此列,此列是另以 HTML 表格解析確認。」
- 問題:這是整理過程的內部說明,提到的「vars.py 腳本」是工具細節,和原文內容無關,讀者看不懂。表格內容本身沒錯,`createworkorder` 列在 HTML 中確實只有 Read。
- 建議修正:整段刪除。若要保留,可縮成:「註:`createworkorder` 一列依原文表格列在此處。」
