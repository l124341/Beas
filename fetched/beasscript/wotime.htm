wotime


Contents

Creates Work order-Time-Entry

 

Important information

The time receipt uses "old" objects which use additional instance variables.

If the variable is defined, the variables have higher priority than the properties.

This functionality cannot be deleted, otherwise compatibility to old customization functions would be lost.

 

Example:

setvar=e_whscode=B

If this variable is defined, the system uses WareHouse "B" for all Bill of Material positions.

 

Problem:

After the first transaction, the system always writes the Default warehouse in the instance variables.

If you make a second transaction in the same window, it uses the same warehouse from the first transaction.

 

Workaround:

Make a sandbox with pushvar and popvar

 

// Save current variables (Sandbox)

pushvar

// now make the time receipt

declare=wotime=...

...

// at end restore all variables

popvar

 

 

Start work time: see wostart

Quantity in Confirm Quantity

The Confirm UoM can be defined in

Routing Position -> Extended -> Confirm in units and -> Factor per inventory UoM

 

The system calculates
QuantityGoodRUoM * Factor per Invent

 

Example:

Stock Unit = kg

Consumption Unit of Assembly = g

Factor = 1000

 

Routing Position

Confirm Unit = ml

Confirm factor = 3

 

Confirm Quantity in Confirm Unit * Confirm Factor / Consumption Factor = Quantity in Stock Unit

Example:

1ml * 3  = 3 g / 1000 = 0.003 kg

 

Calculation to Stock Unit of Assembly

 

Confirm Quantity in Confirm Unit / Confirm Factor / Consumption Factor = Quantity in Stock Unit
