Beas Service Layer


Contents

The Beas Service Layer is a middle layer between the application, front end, or another back end and the database. It is a new generation extension API for consuming Beas and SAP Business One data and services.

BSL uses ODATA syntax but IS NOT FULLY compatible with this protocol and some functionalities are not implemented in the current protocol.

 

With BSL you can create WEB Applications and services without developing a backend. BSL is working the same way as the SAP Service Layer.

 

It is possible to use BSL via the common service and HTTP.

The components in the Beas core are:

•OData Server

•WEB Server

•HTTP Server

Additional components or services are not required.

Questions and answers

What is possible with BSL?

•Reading data from multiple Beas and SAP objects, for example item master data.

•Creating Beas and SAP documents.

•Changing and deleting entries.
Do I have access to all Objects?

Not all Objects available currently, but the functionality is extended to more objects in each new version.
Can I use BSL with MSSQL?

BSL is compatible with both MSSQL and HANA databases. It generates database optimized SQL statements.
Is BSL (addtitional middle layer) slow?

Beas does not use any additional tools. All required middle layers are completely integrated and no additional interfaces are required. This results in a solution with increased performance.
What about security?

If you use BSL via HTTP, security concerns may emerge, but in a normal use case this solution only needs to be used internally. If you need access to BSL externally, you must use an HTTPS proxy server.

 

If the user made a login in the WEB Server (example web application), with the current browser session, the user has full access to the complete functionality of the BSL. Currently it is not possible to define any access rules.
How does the communication work?

BSL uses ODATA. The data is transferred using JSON. ODATA 2, ODATA 3 and ODATA 4 are partially supported. Additional functions are supported, that are not ODATA standard. The interface is optimized for the requirements of BEAS and SAP.

 

BSL supports additional formats for the returned data, for example:

•different JSON variants

•XML

•CSV

•HTML
Can I access custom tables, fields or functions?

SAP UDF's are supported in most of transaction documents.
With the customization tool it is possible to create own objects or you can add additional fields and functions to standard objects.
Is it compatible with Microsoft products, Crystal reports and other tools with general ODATA support?

Currently Beas BSL is not compatible with these products.
